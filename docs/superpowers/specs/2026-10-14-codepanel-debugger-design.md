# 代码演示与调试器面板设计

## 调查结论

`src/components/CodeLine.tsx` 的 `highlightCode` 先转义源码、再分多轮正则生成 `<span>`。Java 关键字列表包含 `class`，后续匹配会命中刚生成的 `class="code-keyword"` 属性；实测输出包含 `<span <span class="code-keyword">class</span>="code-keyword">...`，浏览器因此将标签结构解析错乱。注释、字符串和数字正则也可能处理先前生成的标签。根因是对带 markup 的字符串继续运行 tokenizer。

三个算法统一使用 `AlgorithmStep`：`variables` 存放每一步局部状态，`pointers` 存放画布指针，`array` 是该步骤的数组快照。UI 可从这些通用字段生成调试视图，不需要修改算法行为或单独维护三套渲染。

## 决策

1. 用单次扫描 tokenizer 替换多轮 HTML 字符串正则；匹配注释、字符串、数字、标识符及普通文本，并在输出时转义 token 内容。语法颜色保留，字符串/注释内的关键字不再二次着色。
2. 将代码行展示与 `VariablesPanel` 组合成通用调试器区域：stack frame 显示本步骤局部标量及其值/示意栈地址；heap 区显示 `nums` 引用及数组每格的示意地址、索引、值和颜色。地址明确标为教学用示意地址，不冒充运行时真实地址。特殊表达式型变量（例如 `nums[i]`、`p0 < p1`）不作为局部变量名；数组状态统一以 heap 快照表达。
3. 使用现有步骤数据驱动所有状态，避免扩展算法接口或引入状态库。初始化、比较、交换、移动、完成步骤均需可显示；无有效指针/标量时仍保留可读空态。
4. 对画布做范围受控的可读性优化，不改变三种算法语义：避免窄容器中调试器/画布横向溢出；保留现有语义指针与分区标注，确保三种算法的指针组合均可辨识。

## 验证策略

- 生产构建与 ESLint。
- 浏览器回归检查四种语言代码 DOM 无 `class=`/标签源码泄漏，语法高亮仍存在。
- 切换三种算法并推进步骤，确认代码行高亮、stack frame、heap 地址/数组值、Canvas 指针标注同步变化且无运行时异常。
- 至少检查长数组及不同窗口宽度下的溢出/布局表现。
